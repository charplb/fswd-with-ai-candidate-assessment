Assessment 00 · Brief

Product Management Module

Build a functional module using Laravel, MySQL, React JSX and Inertia.js. Tailwind CSS is optional; functionality and code structure have priority.

Project requirements

Each product belongs to one category.

100 Points
  • Category
  • Name
  • Description
  • Price
  • Stock quantity
  • Active status

Data relationship

The implementation must enforce this relationship in the database and models.

Category
Has many products
1 → N
Product
Belongs to category

Allowed

  • VS Code and terminal
  • Laravel Artisan commands
  • Official Laravel, React and Inertia documentation
  • The instructor-approved clean project

Not allowed

  • Any AI assistant or AI-powered extension
  • Existing CRUD code or previous projects
  • Tutorials, copied snippets or help from another person
  • Hidden external communication during the assessment

Question 01

Database Migrations

Create the database structure and enforce the required relationship behavior.

Requirements

Create the migrations needed for categories and products.

20 Points
  1. A category has a name.
  2. A product belongs to one category.
  3. A product has: name, description, price, stock quantity and active status.
  4. Deleting a category that contains products must not be allowed.
  5. Product names must be required.
  6. Price and stock must have default values.

Expected evidence

database/migrations/...create_categories_table.php
database/migrations/...create_products_table.php

Run the migrations successfully and be prepared to explain the foreign-key delete behavior and your selected column types.

Question 02

Laravel Models & Relationships

Create the Category and Product models with safe mass assignment, casts and navigable relationships.

Requirements

Both relationship directions must work.

15 Points
  1. Create the Category and Product models.
  2. Add the correct relationships.
  3. Add the required $fillable fields.
  4. Add suitable casts for product values.
  5. Allow access to the product’s category from Product.
  6. Allow access to all category products from Category.

Expected evidence

app/Models/Category.php
app/Models/Product.php

Be prepared to explain why each field is fillable, which product fields require casts and how Eloquent resolves both relationship methods.

Question 03

Product Controller & CRUD

Connect validated Laravel actions to paginated Inertia pages.

Required methods

Use route model binding where appropriate.

25 Points
index · create · store · edit · update · destroy
  1. The products list includes each product’s category.
  2. Products are paginated.
  3. Create and Edit receive the categories list.
  4. Store and Update validate submitted data.
  5. After saving, redirect to the products index.
  6. After deleting, redirect to the products index.

Expected evidence

app/Http/Controllers/ProductController.php

Demonstrate both valid and invalid submissions. The controller should load only the data needed by each page and should not trust client-supplied values without validation.

Question 04

Routes & Application Flow

Define the Product CRUD routes, then explain the complete request/response path.

Requirements

The Product module does not require a Show page.

15 Points

Create the required Laravel routes for Product CRUD. Use the project’s authenticated route group when authentication is available.

Route::resource('products', ProductController::class)->except('show');

Explain what happens when the user:

  1. Opens the Create Product page.
  2. Submits the form.
  3. Opens the Edit Product page.
  4. Updates the product.
  5. Deletes the product.

Expected evidence

routes/web.php

Your explanation should connect the named route, HTTP method, controller action, validation, database operation, Inertia page or redirect, and React interface.

Question 05

React JSX & Complete CRUD Connection

Build reusable Inertia pages that display, create, edit and delete products.

Required files

The form must be reused by Create and Edit.

25 Points
resources/js/Pages/Products/Index.jsx
resources/js/Pages/Products/Create.jsx
resources/js/Pages/Products/Edit.jsx
resources/js/Components/ProductForm.jsx

Requirements

  1. Index displays paginated products and pagination controls.
  2. Each product shows its category.
  3. Index contains Create, Edit and Delete actions.
  4. Create sends a Store request.
  5. Edit sends an Update request.
  6. Validation errors are displayed beside relevant fields.
  7. Submit buttons are disabled while processing.
  8. The form is reusable between Create and Edit.

Expected evidence

Run the complete interface. Demonstrate a valid create, invalid create, edit, delete and pagination behavior. Be ready to trace one button click from JSX through Laravel and back to the browser.
